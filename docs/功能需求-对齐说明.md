# 约麻功能需求对齐说明

**文档性质**：在《约麻小程序开发需求设计书》（V1.1）与当前仓库实现之间建立可追溯映射，供验收、排期与联调使用。  
**基线代码**：`yuema-miniprogram`、`yuema-server`；数据库脚本 `yuema-server/sql/init.sql`。  
**约定**：下文 HTTP 路径均相对于后端 `context-path` **`/api`**（与 `application.yml` 中 `server.servlet.context-path` 及小程序 `apiBaseUrl` 一致），例如完整 URL 为 `https://host:8080/api/room/list`。

## 1. MVP 与代码对齐验收清单

每条包含：**小程序页面**、**HTTP/WebSocket**、**验收要点**、**与 PRD 差异**。

### 1.1 认证与个人中心

| 能力 | 页面 / 入口 | 接口 | 验收要点 | 与 PRD 差异 |
|------|----------------|------|----------|-------------|
| 微信登录 | `pages/login/index` | `POST /user/login` | code 换 token；`NEED_PROFILE` 时引导补资料 | PRD「一键头像昵称」一致；无 unionid 单独说明 |
| 拉取资料 | `pages/user/index` 等 | `GET /user/info` | 返回昵称、头像、手机、level、战绩字段等 | 无「个性签名」字段（`UpdateUserDTO` 未包含） |
| 更新资料 | 个人中心弹窗 | `PUT /user/info` | 可改昵称、头像 URL、手机 | 手机为**手动写入**；非微信 `getPhoneNumber` 组件 |
| 上传头像 | 个人中心 / 登录完善 | `POST /user/avatar`（multipart） | 返回可访问 `avatarUrl`；需配置 downloadFile 合法域名 | PRD 未区分 URL 头像与文件上传 |
| 战绩统计 | 个人中心 | `GET /user/stats` | totalGames、winGames、winRate 等 | PRD「段位系统」仅 level 映射展示名，无独立段位算法说明 |
| 历史战绩分页 | `pages/user/history` | `GET /user/game-records` | 分页、按结束时间倒序 | 对应 PRD「历史查询」中用户维度部分 |

### 1.2 首页推荐

| 能力 | 页面 | 接口 | 验收要点 | 与 PRD 差异 |
|------|------|------|----------|-------------|
| 附近牌局 | `pages/index/index` | `GET /room/list?longitude&latitude` | 有定位时带参；无定位仍可请求 | 列表条数前端截取展示与 PRD「推荐」一致即可 |
| 附近场地 | 同上 | `GET /venue/nearby` | 有定位时附近；否则可回落 `GET /venue/list` | PRD「地图/列表切换」若未做，仅列表即算 MVP 现状 |
| 登录门禁 | `onShow` | — | 无 token 重登 `pages/login/index` | — |

### 1.3 牌局

| 能力 | 页面 | 接口 | 验收要点 | 与 PRD 差异 |
|------|------|------|----------|-------------|
| 创建牌局 | `pages/room/create` | `POST /room/create` | 玩法、人数、时间、场地/坐标、底分台费、`gameRules` | PRD「缺人自动匹配」**未实现** |
| 编辑牌局 | 详情（房主） | `PUT /room/update?roomId=` | 仅**待开始**状态可改 | PRD未单独命名 |
| 删除牌局 | 同上 | `DELETE /room/delete?roomId=` | 仅房主、待开始 | 同上 |
| 加入 | 详情/扫码 | `POST /room/join` | roomNo；满员/已结束失败提示 | PRD「链接加入」依赖分享链路，需人工点卡片验证 |
| 详情与成员 | `pages/room/detail` | `GET /room/info?roomId=` | room + members | PRD写「detail」，实现为 **`/room/info`** |
| 我的牌局 | `pages/room/list?type=my` | `GET /room/my` | 仅当前用户相关 | 对应「我的牌局」 |
| 开始 / 结束 | 详情 | `POST /room/start?roomId=`、`POST /room/end?roomId=` | 房主权限；状态流转 | PRD「开局确认（人到齐）」**无单独接口**，现为直接 start |
| 离开 / 踢人 / 转让 | 详情 | `POST /room/leave`、`/room/kick`、`/room/transfer` | 房主不可 leave（须先转让或结束） | 与 PRD「成员管理」一致 |
| 邀请码 / 小程序码 | 详情 | `GET /room/qrcode?roomId=` | 返回 `qrUrl`、`roomNo`；需配置 `yuema.public-base-url` | PRD「房间二维码」一致 |
| 实时同步 / 聊天 | 详情 | 见 **§3.3 WebSocket**；历史 `GET /chat/list` | 进房 join、发消息、拉历史 | PRD「语音/表情」**未实现** |

### 1.4 计分

| 能力 | 页面 | 接口 | 验收要点 | 与 PRD 差异 |
|------|------|------|----------|-------------|
| 提交一局 | `pages/score/record`、详情入口 | `POST /score/record` | 同局重复提交返回业务码（如 409 ROUND_EXISTS） | PRD「多种记分模式」依赖 `scoreType` 等字段录入 |
| 当前汇总 | 详情 / 记分 | `GET /score/summary?roomId=` | 每人累计分 | 一致 |
| 全部明细分条 | 详情 | `GET /score/list?roomId=` | 按局可聚合展示 | PRD写 `history`，实现为 **`/score/list`** |
| 按局查询 / 删局 | 历史 / 房主 | `GET /score/round`、`DELETE /score/round` | 删局：房主或**该局记分人** | PRD写「删除需他人确认」；现为**权限删除**，无投票删除 |
| 结算账单 | 详情 | `GET /score/settlement?roomId=` | 返回 `settlements`、`isValid`（**总分和为 0**） | 金额字段当前为 `amount`≈分数（注释：1 分=1 元），**未乘底注**；与 PRD「台费/底注规则」需产品确认后写死验收 |
| 改分申请 / 投票 | 详情 | `POST /score/modify-request`、`/modify-vote`、`/modify-cancel`、`GET /score/modify-pending` | 房主发起、他人投票 | 与 PRD「记分修改需确认」一致 |

### 1.5 场地（不含在线预订与支付）

| 能力 | 页面 | 接口 | 验收要点 | 与 PRD 差异 |
|------|------|------|----------|-------------|
| 场地列表 | `pages/venue/list` | `GET /venue/list` | 营业中场地 | — |
| 附近场地 | 同上（若有定位） | `GET /venue/nearby` | 距离排序与条数 limit | PRD「地图模式」未要求 MVP 必测 |
| 场地详情 | `pages/venue/detail` | `GET /venue/detail?venueId=` | 图文、地址、电话等 | — |
| 包间列表 | 详情内 | `GET /venue/rooms?venueId=` | 包间类型与价格展示 | **预订、支付、订单**已决议 **P1+**，本段验收不包含 |

## 3. 附录

### 3.1 PRD §5.3 接口命名 vs 实际路由

| PRD 描述路径 | 方法 | 实际路径（`/api` 下） | 说明 |
|--------------|------|------------------------|------|
| `/api/room/create` | POST | `/room/create` | 一致（前缀 context-path） |
| `/api/room/join` | POST | `/room/join` | 一致 |
| `/api/room/leave` | POST | `/room/leave` | 一致 |
| `/api/room/list` | GET | `/room/list` | 一致 |
| `/api/room/detail` | GET | **`/room/info`** | **命名不同**，参数 `roomId` |
| `/api/room/start` | POST | `/room/start` | query `roomId` |
| `/api/room/end` | POST | `/room/end` | query `roomId` |
| `/api/score/record` | POST | `/score/record` | 一致 |
| `/api/score/update` | PUT | **`/score/modify-request` + 投票** | PRD「单条 update」；现为**改分申请流** |
| `/api/score/summary` | GET | `/score/summary` | 一致 |
| `/api/score/history` | GET | **`/score/list`** | 全量明细，前端按 `roundNo` 聚合 |
| `/api/score/stats` | GET | **`/user/stats` + `/user/game-records`** | 用户维度分散 |
| `/api/score/delete` | DELETE | **`DELETE /score/round`** | 权限见 §1.4 |

未在 PRD 表列出但已实现：`PUT /room/update`、`DELETE /room/delete`、`/room/my`、`/room/kick`、`/room/transfer`、`/room/qrcode`、`GET /chat/list`、计分 `modify-*` 全套。

### 3.2 Tab 与信息架构（PRD §6.2）

| PRD | 当前实现 | 决议 |
|------|----------|------|
| 底部 5 Tab，中间突出「创建」 | 4 Tab：首页 / 牌局 / 场地 / 我的；创建从首页或牌局流程进入 | **V1 信息架构变更**：不强制 5 Tab；若未来对齐 PRD，单独立 UI Story |

### 3.3 WebSocket

- **路径**：与 HTTP 同源前缀下 **`/api/ws/room`**（小程序内由 `apiBaseUrl` 的 `http`→`ws` 拼接，见 `utils/socket.js`）。
- **鉴权**：Query `token`；握手由 `JwtHandshakeInterceptor` 校验。
- **用途**：牌局内实时消息（与 `RoomWebSocketHandler` 一致）；具体 `type`/`payload` 以服务端约定为准做联调验收。

### 3.4 结算逻辑备忘（验收用）

`ScoreService.calculateSettlement`：基于 `getScoreSummary` 的每人 `finalScore`；校验 **各玩家分数之和为 0** 记 `isValid`；`amount` 当前与分数同向赋值（注释标明可按底分调整）。**产品需在 PRD 或验收表中写死：底分、台费是否进入分摊、货币单位。**

## 4. 待产品确认项（影响 Story 验收写法）

以下不影响「当前代码是否存在功能」的判断，但**必须在定稿验收标准前二选一或补充说明**：

1. **手机号绑定**  
   - 方案 A：维持手动输入 + `PUT /user/info` 持久化。  
   - 方案 B：微信「手机号快速验证」组件，后端解密换号（需开发新接口与隐私条款）。  

2. **战绩分享**  
   - 方案 A：仅使用小程序 `onShareAppMessage` / 分享卡片（低成本）。  
   - 方案 B：服务端生成战绩图片 + 朋友圈素材（高成本，需设计与存储）。  

（确认后请将对应验收语句补入 §1.1 / Epic C 相关行。）
